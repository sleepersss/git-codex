恢复资料：任务删除保存在 work 同级的 `backups/mod-extractor-deletions/tasks`，素材删除保存在素材库 `history/deleted-assets`。每个 ZIP 内 `recovery-manifest.json` 记录原路径和 SHA，文件位于 `payload/`；恢复前退出工具，在独立目录解压核对，确认不与现有编号/文件冲突后再放回原位置，并使用现有索引重建流程。不要覆盖已有素材。

本次整个根 work 与旧版软件的清理记录见 `reports/mod-extractor-maintenance-20261027`，恢复归档在 `归档待上传115/WorkspaceWork_20261027`，仅为本地归档。工作区当前只保留 r6 的展开程序；已验收的 r5 原字节可按恢复清单取回。

v3.3-r5 只新增「打开 full.blend 手动删减」：选中已核对的提取任务，打开 full.blend 独立副本，删除多余模型（或源面），按 Ctrl+S 保存到当前文件并退出该 Blender 窗口。工具自动核对保存记录、剩余源数据、保存重载，生成 body.blend、四视图，以及网格/顶点/三角面数量、包围盒和尺寸记录。测量为 Blender 单位下的基础网格，不推断解剖完整度或游戏适配。未保存、模型未删减、空网格或核对失败时不产生新 body；原 full、已有 body 和记录保留。已有结果更新前先备份到任务的 manual-body 会话目录。处理结束后继续用原「保存到素材库」归档，编号、来源和测量记录一并保留。

以下保留 v3.3-r1 身体选择修正的说明：

本版修正自动身体选择的三个问题：

- 上下身、独立皮肤细节、原脖子等来源标签会进入候选；不会再按 `Body_EX2` 名字直接丢弃。名称只是检查线索，不是解剖或皮肤验证结论。
- 有界比较来源声明的切换值，重新计算 Present 派生变量；优先保留有明确互补区域的候选状态。同等或无法比较的身体变体不再按出现顺序决定，保持待核对。
- 不再仅凭 `iuno` 样本名称判定缺口。已知或本次发现的实际肢体缺口仍会停止身体生成；未确认不等于没有身体。

完整模型仍先保存。身体分支会生成 `body-candidates.json` 和中文 `body-review.html`，说明选择、排除、互斥状态与无法判断的条件。完成后点击“查看任务报告 / 日志”优先打开中文报告。独立且有明确源皮肤标签的部件不会仅因尺寸小或未连到最大表面而被删除。来源状态检查上限为 4096 个组合；超限时保留 full 与记录，不凭部分搜索结果输出裸模。

数据保存重载和源子集核对不代表人工视觉、解剖完整性、骨架或游戏适用性通过。结果分别记录 `body_visual_review_status=not_run`、`game_compatibility_status=unverified`；仍需查看真实预览。本版不补面、不替换人体、不修改源 Mod，也不批量迁移已有素材。

已验证范围和剩余限制：

- 回归检查覆盖正文提到的标签、互补状态、互斥状态、未知条件、Present 改写、固定变量以及隔离 Blender 保存重载。另核对了历史四次身体纠正涉及的 19 个实际源标签；本轮没有重新导出这四份真实模型或声称通过其视觉验收。
- **普通入口仍按单个 INI 提取和入库**。整 Mod 的多 INI 聚合及父子目录身份修复不在本版范围；多配置批量入库前应先核对现有记录，避免重复拆分。
- 真正 ZIP/7z 文件仍需先解压；以 .zip 结尾的目录按目录处理。ZZZ 仍没有本机真实样本的全面验收依据。
- 日常运行不依赖 Codex、网络或系统 Python；仍需本机配置的 Blender，已核对专用流程还需 Sword 与 Herta。

构建：`python build_desktop.py`。构建包内 `release.json` 保存代码哈希及设置来源。

运行本目录启动提取工具.cmd，打开包含本次全库成果的正式素材库；程序文件夹整体保留。导入清单与哈希检查记录：`model-library/reports/hsr-corpus-import-20261011.json`。

选择 Mod 文件夹后，自动扫描实际 INI，识别游戏和模型资源。多份配置可在下拉框选择。不会用人物名称限制提取。游戏标记不足时手动选择游戏。真正的压缩文件需先解压；名称以 .zip/.rar 结尾的文件夹可直接选择。

通用流程读取静态 drawindexed 的绑定、顶点、索引和原始属性，生成 models/full.blend；按来源顶点及三角面逐项核对，并在保存、重新打开后再次核对。切换变体全部保留，默认只显示源配置的一套状态，其余网格隐藏。支持数字范围及 auto 绘制，包括按同一 hash 分部件的父子配置和合并变体；不执行 Mod 命令或着色器。支持位置 stride 12/40/56、索引 R16/R32。星铁按 Y 轴朝上转成 Blender 的 Z 轴朝上，源坐标与原始字节不变。

HSR Texcoord stride 8/16 读取独立颜色与半精度 UV，20/28 读取颜色与浮点 UV；12 字节布局根据完整缓冲区数值范围推断，并记录推断说明。不能明确解释的压缩权重只保留原始字节。未恢复游戏骨架、材质着色器、动态计算或滑条；本来依赖游戏原模型的头部等未替换网格不会凭空生成。源贴图、缓冲区和配置保留在来源备份中。成功任务的临时 input/Sword 副本由既有清理流程移除，模型、验证、预览和来源备份保留。不能安全识别的绑定、动态 drawindexed 或越界数据会停止并显示具体原因。

达妮娅、尤诺的已核对来源清单自动走既有专用流程，其他兼容配置走通用读取；不存在人物白名单。新流程已实测奥古斯塔、珂莱塔及星铁 Evanescia。绝区零尚无本地实样验证，不能视为全量兼容。

先保存完整 Mod 模型，再根据源 INI 的身体标签、明确衣服关闭状态和同一套开关状态选择皮肤部件。识别分开的手、脚和上下身，分析原始皮肤表面的连接及接缝，保存独立 models/body.blend。身体分析使用每次实际绘制的条件，避免不同状态共用范围时丢失标签；带袖、鞋、紧身衣等正向服装说明优先于 nude/arms 字样。身体覆盖范围还与完整源模型比较，局部躯干不能把自身高度当作完整身体。相反的开关分支不会同时拼在一起；无法求值的条件保留为待核对。

检查范围是直立源姿态中的无头身体：躯干、髋部、左右上臂/前臂/手、大腿/小腿/脚以及实际表面连接。头、头发和微小中央源细节开口不作肢体缺失处理，会原样保留并记录；这不代表网格水密。仅在分析中对重合坐标和已有重叠皮肤接缝建立连接，不改变源顶点、不生成新三角面、不补洞或拼造身体。对源标签中混入的独立小饰件保留排除记录。

身体有肢体或连接缺口时只保留 Mod 模型并记录。不能识别身体分组或身体分析异常时标记“待核对”，不影响已通过核对的 Mod 模型入库。批处理实测记录位于 work/hsr-corpus-audit-20261011/repair-index.html；该报告分别列出模型数据核对、身体检查、预览和逐配置执行/重复几何复用证据，不把数据一致性当成人工视觉验收。

独立核对身体是 full.blend 的源三角面子集，坐标、原始属性字节、UV、颜色、权重和已有形态目标保持一致。Blender 压缩法线重新编码允许小于 0.1 度的差异，并记录实测值。素材库完整模型和历史编号不覆盖；旧的“已放弃”记录可追加已核对身体，旧候选及历史保留。

完成后可打开 Mod 模型目录、直接打开裸模、查看报告、保存到素材库。失败时可直接查看本次日志。

本机需要 Blender；已核对专用流程另需授权有效的 Sword 和 Herta。设置保存于 settings.json。界面使用实色 Qt 控件和中文系统字体。源码构建 python build_desktop.py。
